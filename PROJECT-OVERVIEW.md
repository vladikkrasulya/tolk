# Tolk — полное описание проекта

Состояние на 10.11.2026, версия 0.7.0. Более поздние изменения описаны в журнале версий в ARCHITECTURE.md.
Документ для внешнего ревью: что приложение умеет, как это устроено, чем измерено и что ещё в работе.
Пользовательское описание — в `docs/USER-GUIDE.md`, установка — в `SETUP.md`, устройство и журнал версий — в `ARCHITECTURE.md`.

---

## 1. Что это

**Tolk** — личный переводчик и помощник при наборе для macOS, «DeepL на своей модели». Перевод делает собственная
языковая модель на домашнем сервере. Подсказки при наборе — маленькая модель прямо на Mac. В облако по умолчанию
ничего не уходит. Google подключается только как запасной путь, его можно заменить переводом Apple на устройстве
или отключить совсем.

Для чего используется:
- **Рабочая переписка** (adtech: RTB, SSP/DSP, eCPM, floor price, fill rate…), RU ↔ EN, в Slack, Teams, Telegram и почте.
- **Семейная и бытовая переписка**, RU / UK / EN.

Главный сценарий: выделил текст в любом приложении, дважды нажал ⌘C — рядом с курсором появляется окно с переводом,
который печатается по мере генерации. Оттуда перевод можно скопировать, вставить на место выделения или ответить
собеседнику на его языке. Второй сценарий: пишешь по-русски прямо в чате, под полем появляется перевод на язык
собеседника, Tab вставляет его («Перевод при наборе»).

Платформа: macOS 14+, Apple Silicon. У автора MacBook Pro M1 Max, 32 ГБ. Одну и ту же систему поставили и на Mac
друга с моделью на Windows-ПК с видеокартой 12 ГБ (см. раздел 4).

## 2. Из чего состоит система

```
 MacBook (Tolk.app)                                        Домашний сервер (Windows, GPU 6 ГБ)
 ┌──────────────────────────────────────────────┐   HTTP   ┌───────────────────────────────────────────┐
 │ двойное ⌘C, окна, горячие клавиши             │ ───────▶ │ Ollama :11434, 2 параллельных слота        │
 │ движок TolkCore: промпты, правила, глоссарий, │ ◀─────── │ gemma-translate (Gemma 4 26B MoE, Q4_K_M, │
 │   проверки, кеши, история                     │  поток   │   num_ctx 8192)                           │
 │                                               │          │ qwen-translate (Qwen 3.6 35B-A3B) — запас  │
 │ автодополнение: llama-server 127.0.0.1:8178   │          └───────────────────────────────────────────┘
 │   Gemma 4 E2B abliterated (3,4 ГБ, Metal)     │   если сервер недоступен:
 └──────────────────────────────────────────────┘   Google (в интернет) / Apple Translation (на устройстве) / ничего
```

**Swift-пакет, три цели.** Сборка только Swift 6.2 Command Line Tools, без Xcode; режим языка Swift 5.
- `TolkCore` — движок без AppKit: модели языков и запросов, провайдеры, промпты, правила и глоссарий, проверки,
  кеши, история, чистая логика автодополнения и «Перевода при наборе». Всё здесь тестируется из командной строки.
- `Tolk` — приложение в строке меню (AppKit, местами SwiftUI): ввод, окна, автодополнение, OCR, документы.
- `tolk-cli` — инструмент разработчика: перевод из терминала, все режимы движка, корпуса и встроенный самотест.

Объём — около 31 тыс. строк Swift в 137 файлах. Версии — от 0.1 до 0.7.0, 31 коммит.

## 3. Что приложение умеет

### 3.1. Быстрый перевод по двойному ⌘C (всплывающее окно)
- `Input/DoubleCopyMonitor.swift` ловит два ⌘C подряд (интервал настраивается, по умолчанию 0,4 с) через CGEventTap
  (нужен «Универсальный доступ») и берёт текст из буфера обмена.
- `UI/TranslationPopupController.swift` — плавающая панель (`NSPanel`), которая не активирует Tolk: исходное
  приложение остаётся впереди. Перевод печатается потоком.
- Направление определяется само (`LanguageDetector`): русский и украинский уходят в английский, остальное — в русский.
  Можно выбрать любую из 24 пар языков.
- Тон: Авто / Чат / Письмо. В режиме «Авто» тон берётся из приложения, откуда скопирован текст (`toneByApp`):
  Slack, Telegram, Teams → чат; Mail, Outlook → письмо.
- **Сноски** по спорным терминам (`NotesProvider.notes`) — отдельный JSON-запрос, например «wins → винов: в RTB это
  выигранные аукционы». Кнопки «Так и оставить» и «Заменить» (с повторным переводом).
- **Обратный перевод** — проверка, что смысл не уехал.
- **Варианты слова** по щелчку на слове (`alternatives`) и **«Варианты перевода»** всего текста: 2–3 версии с
  пояснением, чем они отличаются (кнопка открывает большое окно с тем же текстом, тоном и контекстом).
- **Добавить в глоссарий** прямо из окна.
- **Редактор** (`Refine.swift`) — второй проход, который убирает кальки. Есть «Вернуть» и страховка (`RefineGuard`):
  правка отбрасывается, если пропал вопрос или поменялось приветствие.
- **Ответить** (`UI/ReplyPanelController.swift`): пишешь ответ по-русски и получаешь его на языке собеседника с учётом
  его сообщения. «Вставить в чат ⌘↩» вставляет текст, но никогда не отправляет. **Готовые ответы** («Подтвердить»,
  «Смотрим», «Детали?», «Созвон?», «Отказать», ⌘1…⌘5) пишут короткий ответ по смыслу кнопки, затем он переводится.
- **Память переписки** (`ThreadMemory`): короткие тексты из того же приложения за 5 минут получают до трёх прошлых
  реплик как контекст. Пересчёт часовых поясов в окне и в карточке «Проверка» — без модели (`TimezoneConverter`).
- Строка статуса: модель, время до первого слова, токены в секунду, метка «из кеша» с «↻ заново» и предупреждения
  проверки (⚠).

### 3.2. Большое окно (главное окно приложения)
Разделы (⌘1…⌘7): Перевод, Фото и скриншоты, Документы, История, Глоссарий, Настройки, Как пользоваться.

**Страница «Перевод»** имеет три режима: «Перевод», «Ответ», «Составить».
- **Живой перевод при наборе.** Переводится только изменившийся хвост: `IncrementalTranslation.swift` разбивает текст
  на предложения, неизменные берутся из кеша, а с изменённым хвостом в запрос уходит контекст. ⌘↩ переводит всё
  заново; после паузы 2,5 с на текстах до 600 символов один раз идёт «финальный проход» по всему тексту.
- **Пары предложений** (`SentencePairs`, без модели): наведение подсвечивает пару в обеих панелях. Щелчок по
  предложению — карточка «Варианты предложения». Термины глоссария подчёркнуты в переводе.
- **Панель «Подсказки»** (`UI/TranslationHintsPanel.swift`): на широком окне третья колонка, на узком — блок под
  переводом. Карточки: Проверка, Сноски, Обратный перевод (подсвечивает только смысловые расхождения: числа,
  отрицания, имена, термины — `BackDiff`), Варианты слова, В глоссарий, Правка редактора, Варианты перевода,
  «Что он имел в виду» (смысл, тон, до пяти терминов). Запросы стартуют через 1,5 с после готового перевода, набор
  их отменяет, одновременно идут не больше двух — по числу слотов Ollama.
- **Переписывание** (`RewriteBar`): Короче / Мягче / Твёрже / Проще / По-деловому / Прямо и «ты» / «Вы». Страховка
  `TranslationCheck`: правка отбрасывается, если пропали числа, ссылки, вопрос или приветствие, появились новые
  числа или сменились местоимения. «Правка» показывает было / стало, «Вернуть» откатывает.
- **«Ответ»**: сообщение собеседника и его перевод сверху, свой ответ ниже, язык собеседника определяется по его
  сообщению (`translateReply`).
- **«Составить»** (`ComposePanel`, `compose`): тезисы на своём языке → готовое сообщение на языке получателя в тоне
  Нейтрально / По-деловому / Прямо / Дружелюбно + обратный перевод отдельным запросом. Предупреждает, если число,
  время или дата из тезисов пропали или появились новые.
- «Последние» — переводы из истории без запроса к модели; файл, брошенный на страницу, открывается в «Документах».

**Остальные разделы**
- **Фото и скриншоты** (`ImageTranslate/`): перевод картинки или области экрана (⌥⇧S) через Vision OCR, длинные
  тексты разбиваются на части. Результат идёт в раздел, если Tolk был активен, иначе — во всплывающее окно.
- **Документы** (`Documents/`): PDF (текст и OCR), Word, RTF, ODT, HTML, TXT, MD. Перевод по абзацам, пауза и
  продолжение, экспорт в DOCX/RTF/TXT/MD, в том числе двуязычный.
- **История** (`TolkCore/History/HistoryStore`): JSONL с правами 0600, до 3000 записей, поиск; документы не пишутся.
- **Глоссарий** (`Glossary/`): редактор файла правил с CSV-импортом и экспортом, следит за изменениями файла на диске.
- **Быстрые действия** (`Actions/`): ⌃⌥T «Перевести и заменить», ⌃⌥P «Причесать и заменить» (правка на том же
  языке), ⌃⌥L «Исправить раскладку» (RU/UK ↔ EN по словам, без модели; `Engine/LayoutFix.swift`). Сочетания меняются в
  настройках.
- **Экран первого запуска**, страница «Как пользоваться», настройки на трёх вкладках
  (Перевод · Автодополнение · Общие).

### 3.3. «Перевод при наборе»
Режим включается по ⌃⌥R для приложения (или автоматически, если последнее сообщение собеседника на другом языке;
по умолчанию выключен). После паузы 500 мс весь текст поля переводится на язык собеседника (`TolkCore/TypeTranslate.swift`)
с учётом его сообщения, тона приложения и памяти переписки. Под полем серая строка, Tab вставляет перевод через
буфер с восстановлением (⌘Z работает), Esc оставляет свой текст, Enter не перехватывается. У режима нет запасного
пути: при выключенном сервере он молчит, текст не уходит в Google. Поля те же, что у автодополнения; полей TextEdit
(NSTextView) режим тоже касается.

### 3.4. Автодополнение во всей системе (в духе Cotypist)
Серый текст после курсора в любом приложении: Tab — следующее слово, → — подсказка целиком, ⌥Tab — обычный Tab,
Esc — замолчать в этом поле. По умолчанию выключено.

**Модель на Mac.** Подсказка должна появляться за 100–300 мс, поэтому сеть не годится. Tolk сам запускает
`llama-server` (Homebrew llama.cpp) на 127.0.0.1:8178 с параметрами `-c 4096 -ngl 99 -fa on -np 1`.
Модель — Gemma 4 E2B abliterated Q4_K (3,4 ГБ, около 3,6 ГБ памяти; репозиторий `huihui-ai`, файл Q4_K).
В настройках по умолчанию записано имя файла E4B, нужный файл выбирается в списке «Модель».

**Чтение поля** (`Autocomplete/FocusedField.swift`) — через Accessibility: текст перед курсором и рамка курсора.
Для Electron и WebView (Slack, Teams) — через AX text markers, для NSTextView — отдельная ветка. Каждый отказ
пишется в лог с шагом, на котором чтение сорвалось.

**Контекст переписки** (`ScreenContext.swift`) — видимые сообщения окна: сначала через AX, запасной путь —
OCR снимка окна. Контекст стоит в начале промпта, чтобы KV-кеш llama.cpp переиспользовался при наборе.
Снимок не пересчитывается, пока картинка почти не изменилась (сигнатура 32×32, порог 0,4 % клеток), смотрит на экран
по событиям (другое окно, поле очищено, прокрутка) и не чаще, чем раз в 15 с в покое. Для OCR есть отдельный выключатель.
До трёх последних сообщений пользователя из того же приложения (из `StyleMemory`, только при включённом обучении)
идут в промпт перед перепиской.

**Промпт** (`AutocompletePrompt.swift`) — для Gemma 4 с чат-шаблоном: правила, примеры и переписка в ходе пользователя,
набранный текст — начало ответа модели (`useChatPrefill`); для других моделей — сырой текст без шаблона. Промпт
никогда не кончается пробелом. **Token healing** (`useHealing`): недописанное слово убирается из промпта, а GBNF-грамматика
заставляет ответ начаться с него; окончания слов посреди слова: 0 → 9 из 15.

**Запрос на каждое нажатие** (с 0.6.7): пауза 20 мс (60 мс при частом наборе), устаревшие запросы отменяются.
Правильная подсказка появляется в 23 случаях набора из 54 вместо 14 (+64 %) при той же точности первого слова.

**Отсев плохих подсказок**
- Порог уверенности (`TolkCore/AutocompleteTuning.swift`): `n_probs` от llama-server, подсказка обрезается на первом
  неуверенном токене, полслова не показывается. Частота «реже / обычно / чаще» — это пороги 0,6/0,35, 0,5/0,35, 0,3/0,3.
- Фильтры отбрасывают выдуманные числа, разметку, эхо шапки и повторы. Нет подсказок в поисковых строках, адресных
  строках, ячейках таблиц, маленьких и логинных полях.

**Безопасность** (`TolkCore/AutocompleteSafety.swift`)
- Перед вставкой по Tab или → и перед удалением символов автоисправлением поле перечитывается не дольше 25 мс.
  Если изменились процесс, элемент или текст перед курсором, ничего не вставляется и клавиша уходит в приложение.
- При системном защищённом вводе (`IsSecureEventInputEnabled`) и в менеджерах паролей, терминалах и IDE ничего не
  читается и не показывается. Свои окна Tolk тоже молчат (`focusIsInOwnWindow`).
- Чтение Accessibility в обработчике клавиш ограничено по времени.
- Буфер обмена читается только при включённом переключателе.

**Жизненный цикл сервера** (`TolkCore/AutocompleteServerLogic.swift`, `LocalModelServer.swift`)
- `llama-server` запускается под `sh`-обёрткой, которая убивает его, когда пропадает Tolk, — даже после `kill -9`.
- По pid-файлу Tolk отличает свой «осиротевший» сервер (его перезапускает) от чужой программы на порту (её не
  трогает и пишет «порт занят»).
- Ошибки видны в логе, в настройках и в меню, есть кнопка «Повторить». После падения сервер сам перезапускается
  через 2, 10 и 60 с.

**Мгновенная помощь без модели**
- `Autocorrect` — на NSSpellChecker; осторожный: не трогает первую букву, бренды и сленг.
- `EmojiSuggestions` — `:fire`, `:огонь`.

Эти функции работают, даже когда модель выключена.

**Статистика** (`TolkCore/AutocompleteStats.swift`, блок в настройках и строка в меню, `tolk-cli --ac-stats`): показано
и принято слов, сэкономленные нажатия, медиана задержки, разрезы по дням, моделям и приложениям. Файл
`autocomplete-stats.json`, только числа.

**Дополнительно**
- Инструкции в промпте: общие, для конкретного приложения и по тону; подходящие строки глоссария.
- `StyleMemory`: по желанию — локальное хранилище отправленных фраз, зашифрованное AES-GCM. Ключ лежит в файле
  `style.key` (0600) рядом с хранилищем, а не в «Связке ключей»: с самодельным сертификатом «Связка» просила пароль
  после каждой пересборки. «Удалить выученное» стирает файл и ключ.
- Режим «на батарее»: реже, без снимков экрана, короче. Всё по умолчанию выключено.
- Журнал отладки на 1 час: локальный jsonl и снимки вокруг курсора.

### 3.5. Правила, профили, глоссарий
- Файлы Markdown в `~/Translate`: `rules.md` — профиль «Работа», `home.md` — профиль «Дом» (по умолчанию). В каждом
  раздел о стиле и строки вида `- термин → перевод`. Если файла нет, действуют встроенные правила (`DefaultRules.swift`).
- Раздел о стиле идёт в каждый запрос. Из глоссария берутся только строки, термины которых встретились в тексте
  (`RulesStore.promptBlock`):
  - латиница совпадает целым словом с обычными окончаниями;
  - кириллица — по основе с коротким окончанием.
- Пары глоссария разворачиваются в сторону языка перевода: файл смешивает «en → ru» и «ru → en», а Gemma иначе
  копировала не ту сторону.
- У каждого профиля может быть своя модель. Профиль переключается в меню.

### 3.6. Качество перевода и проверки
- **Промпты** (`Prompt.swift`) нейтральные, без предметной области; область задаёт профиль. Для каждого языка есть
  явные указания против калек. Единые правила: формат чисел языка перевода, одна форма обращения, имена
  транслитерировать. В 0.7.0 добавлены правила для типичных ловушек RU→EN («убрать от нас / подливать нам», лить,
  сабы, net-30, «до выяснения»…) и EN→RU (please advise, moving forward, circle back…).
- **Стабильность:** `seed: 42` и `temperature: 0.1` дают одинаковый перевод одного и того же текста.
- **Проверка после перевода** (`TranslationCheck.swift`): потерянные ссылки, числа, суммы и время уходят в
  предупреждения. **Детектор калек** (`CalqueDetector.swift`, около 60 записей) добавляет «калька: …».
- **Кеши:** кеш готовых переводов (LRU 200 записей / 2 МБ / 24 ч, только в памяти, ключ — SHA-256 итогового промпта,
  текста и модели), кеш предложений при живом наборе, отдельный кеш сносок. Варианты, переписывание и «Что он имел в
  виду» не кешируются.
- **Размышление модели** отключается через `reasoning_effort: "none"` в `/v1`. С ним ответ шёл бы около минуты.
- **Маскирование сущностей** (`EntityMasker`) написано, но выключено: Gemma и так сохраняет ссылки и макросы.

## 4. Модели и замеры

### Перевод (домашний сервер, Ollama)
- `gemma-translate`: Gemma 4 26B MoE (128 экспертов, 8 активных, около 4B активных параметров), Q4_K_M. Видеокарта на
  6 ГБ, поэтому модель частично считается на процессоре.
- **`num_ctx 8192` вместо 32768**: генерация около 26 против 22 ток/с (+15–20 %), первое слово так же быстро (~1,1 с).
  Запрос с другим `num_ctx` заставляет Ollama перезагрузить модель (~30 с), поэтому значение задаётся только в
  `Modelfile`. Старая модель осталась как `gemma-translate-32k`.
- Скорость на видеокарте 6 ГБ: 22–26 ток/с, обычный текст за 2–7 с. Холодная загрузка — 30–150 с. На Windows-ПК
  друга с видеокартой 12 ГБ около 55 ток/с.
- Рабочий корпус (50 текстов adtech): 50 из 50 без ошибок, около 5,9 с на текст. Gemma против Qwen — 21 / 11 / 18
  (лучше / хуже / одинаково).
- Бытовой корпус (50 текстов RU/UK/EN): текстов с кальками было 17, стало 4. Оценка сделана без носителя языка.
- **Корпус ловушек** (321 текст: 81 написан вручную, 240 синтетических, среди них настоящее сообщение пользователя из
  Slack): автопроверка 299 → 313 из 321 на `gemma-translate` после правок промпта; `qwen-translate` с тем же промптом
  290 из 321 (слабее на жаргоне), поэтому основная модель — Gemma.

### Автодополнение (Mac, llama.cpp + Metal)
Сравнение на 54 обрывках из реального журнала набора и рабочего корпуса. Критерий строгий: первое слово или
окончание должно совпасть с тем, что человек напечатал на самом деле.

| Модель | Показано / верно (без порога) | С порогом 0.6 | Задержка тёплого запроса | Память |
|---|---|---|---|---|
| Gemma 4 E4B it (прежняя) | 35 / 8 | 8 / 5 | ~250 мс | 5,3 ГБ |
| **Gemma 4 E2B abliterated** (текущая) | 38 / 7 | 11 / 4 | **~105 мс** | **3,4 ГБ** |
| Qwen 3.5 4B abliterated | 34 / 8 | 12 / 5 | ~225 мс | 2,7 ГБ |
| Gemma 4 E4B abliterated | 40 / 8 | 10 / 6 | ~160 мс | 5,3 ГБ |
| Gemma 4 E4B abliterated, чат-шаблон | 37 / 10 | 9 / 8 | ~530 мс | 5,3 ГБ |

- Разница между моделями с сырым промптом в пределах шума (1–2 случая). E2B выбрана как самая лёгкая: в 1,5–2 раза
  меньше работы видеокарты на подсказку — меньше нагрев и шум.
- Token healing поднял правильные окончания слов посреди слова с 0 до 9 из 15 (+50 мс на запрос). Запрос на каждое
  нажатие дал +64 % случаев с верной подсказкой.
- «Выбор слов» (logit_bias к частым словам пользователя) на наборе случаев выигрыша не дал; оставлен как опция.
- В живой работе: 9.11 (E4B) показано 245, принято 58 (24 %); 10.11 (E2B) показано 59, принято 17 (29 %).
  Выборка мала.
- Отвергнуто: 26B на Mac — около 15 ГБ памяти и нагрев; 26B на сервере для подсказок — около 1,4 с, и модель
  переоценивает свою уверенность.
- Для сравнения: Cotypist тоже работает на llama.cpp, по умолчанию Gemma 4 (E2B); KeyType и TabType (MIT) используют
  сырые промпты, token healing и запрос на каждое нажатие.

## 5. Приватность и безопасность
- Перевод идёт только на сервер пользователя. Google — лишь запасной путь, по выбору; Apple Translation работает на
  устройстве. «Перевод при наборе» запасного пути не имеет.
- Модель подсказок слушает только 127.0.0.1.
- В `tolk.log` нет набранного текста — только длины, время и идентификаторы приложений.
- История — локальный файл с правами 0600. Кеши переводов живут только в памяти. Статистика автодополнения — только числа.
- `StyleMemory` зашифрован, ключ лежит в файле `style.key` (0600), есть «Удалить выученное».
- Защита автодополнения описана в разделе 3.4. Двойное ⌘C и вставка требуют «Универсального доступа»,
  перевод экрана — «Записи экрана».
- Сборка подписывается самодельным локальным сертификатом, чтобы разрешения не слетали после пересборки.
  Распространение — вручную (`scripts/make-dmg.sh`).

## 6. Как проверяется
- В Command Line Tools нет XCTest, поэтому проверки — свой самотест `swift run tolk-cli --self-test`: 777 проверок
  без модели и сети. Они покрывают глоссарий, промпты, проверки перевода, кеши, разбор JSON, страховки редактора и
  переписывания, логику безопасности и сервера автодополнения, пары предложений, раскладку, часовые пояса, ловушки.
- `tolk-cli` гоняет все режимы на живой модели, корпуса в `~/Translate/test-corpus` дают сравнения «было / стало»;
  `tolk-cli --trap-corpus` прогоняет корпус ловушек.
- Правило проекта: тесты «невидимые» — без окон на экране, смены фокуса, синтетических нажатий и изменений буфера.
  Интерфейс проверяется отрисовкой в PNG в окне, которое никогда не выводится на экран (`TOLK_MAIN_SHOT`,
  `TOLK_HINTS_SHOT`, `TOLK_RENDER_POPUP`, `TOLK_RENDER_REPLY` и т. п. в отладочной сборке). То, что так проверить
  нельзя (реальные щелчки, Tab в чужих полях), честно помечается как «не проверено» и проверяется пользователем вживую.

## 7. Как ведётся разработка
- Одна сессия-координатор держит архитектуру, бьёт работу на независимые части и принимает результат.
  Реализацию делают параллельные сессии на более дешёвой модели.
- Каждая сессия работает в своём git worktree и правит только свои файлы. Коммитов они не делают.
- Координатор сводит ветки в проверочной копии, разбирает конфликты (обычно одна строка в списке самотестов),
  собирает, прогоняет самотест и только после согласия пользователя коммитит и ставит сборку.
- Версия хранится в файле `VERSION`. Номер сборки — число коммитов, хеш коммита зашит в `Info.plist`.

## 9. Известные ограничения и открытые вопросы
- Одна точка отказа: если сервер модели выключен, остаётся только запасной путь. Пользователя это устраивает.
- Нет клиента для Windows и Linux. Облачное API (OpenAI-совместимое) по ключу не поддерживается: нет поля ключа и
  ручного ввода имени модели.
- На сервере помещается только одна большая модель: переключение означает перезагрузку на 30–150 с. Два слота Ollama
  делят все запросы — перевод, сноски, обратный перевод, варианты.
- Кеш предложений при наборе не пересматривает ранние предложения, если поздний текст меняет их смысл (⌘↩ перепереводит всё).
- Редактор иногда меняет стилистику там, где не нужно. Тоны «Составить» на коротких тезисах остаются похожими.
  «Наперед дякую» не исправляется.
- Автодополнение: окончания слов посреди слова угадываются только с token healing (9 из 15). Качество меряли на
  маленькой выборке (54 случая) с субъективной оценкой «глупых» подсказок. В настройках по умолчанию записан файл E4B,
  а не E2B: на новой установке модель нужно выбрать вручную.
- Нагрев Mac: основная нагрузка — OCR снимков экрана для контекста (300–500 мс CPU) и частые запросы подсказок. Сам E2B
  даёт около 0,1 с работы GPU на подсказку.
- `↻ заново` при неизменных настройках возвращает тот же текст (фиксированное зерно) — это ожидаемо.
